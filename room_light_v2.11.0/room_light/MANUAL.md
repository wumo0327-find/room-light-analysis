# 使用手册 & 版本更新日志

## 安装与启动

```bash
pip install -r requirements.txt
python main.py
```

**依赖：** Python 3.10+，PyQt6，matplotlib，numpy，openpyxl

## 操作步骤

### 1. 输入房间参数
侧边栏「房间几何」：设置长/宽/高（mm）。

### 2. 添加窗户
侧边栏「窗户」→ 选择朝向 → 「+ 添加窗户」→ 展开卡片设置坐标、尺寸、透射比。  
坐标系：以该朝向墙面左下角为原点，X=距左边(mm)，Y=距底边(mm)。

### 3. 设置材料参数
「材料反射率」：墙/顶/地/室外地面反射率（光学参数，用于采光计算）。

### 4. 设置热工参数（v2.2新增）
「围护结构热工参数」：传热系数 U（W/m²K）、遮阳系数 SC、外墙吸收系数、换气次数、内热扰密度等。

### 5. 设置气象数据
侧边栏「气象数据」→「⚙ 更改气象数据…」，弹窗支持：
- **手动输入**：逐月填写照度(lux)和温度(℃)，可一键填入益阳/北京 TMY 参考值
- **导入文件**：.xlsx/.csv，格式：列A=月份，列B=照度，列C=温度

### 6. 全部分析
工具栏「▶ 全部分析」，弹出进度条窗口，实时显示：
- 采光分析（逐行进度）
- 热环境分析（逐月进度）  
支持**暂停**和**取消**。

### 7. 查看结果
- **建筑视图**：平面图 / 南北东西立面图（含窗户标注）
- **采光分析**：照度热力图 + KPI（Eavg/U₀/DF/WFR）+ 截面分布图
- **热环境**：逐月室温折线图 + 舒适判定 + 热流分解

### 8. 导出结果
工具栏「↓ 导出结果」，勾选需要导出的内容：
- 采光热力图 PNG
- 截面分布图 PNG
- 热环境分析图 PNG
- 光热综合对比图（拼合）PNG
- Excel 报告（含所有数据）

统一设置保存路径和文件名前缀，一次批量导出。

## 项目文件（.rlproj）

格式：JSON，包含全部房间参数和气象数据。

**保存：** 工具栏「💾 保存」（首次弹路径选择，后续直接覆盖）/ 「另存为」  
**打开：** 工具栏「📂 打开」或将 .rlproj 文件**直接拖入程序窗口**  
**向后兼容：** 支持读取所有历史版本（v0.1 ~ v2.2）的 .rlproj 文件，缺失字段自动使用默认值。

### v2.10.2
**修正端墙柱宽错误 + 按现场CAD图纸核实房间/窗户精确尺寸**

背景：用户提供房间411/509的现场CAD平面图（含精确尺寸链），指出程序里
"每个窗边上只有540的遮挡"，与实际画出的端墙柱宽（此前等于整段端墙剩余
宽度，如1540/450/830mm）不符。

诊断：v2.10.0 引入两端外墙翼板时，把柱子宽度设成了"整段端墙剩余空间"，
而不是固定的柱体实际宽度——现场装饰柱本身宽度是固定值（540mm，与窗间墙
宽度数值巧合相同，但概念上是两个不同参数：窗间墙宽度由窗户排布决定，
端墙柱宽是柱体本身的固定构造尺寸），贴在窗户边缘，端墙上柱子之外的部分
应为普通墙体、不参与遮挡。

修正：
- **`core/models.py`**：`ShadingDevice` 新增 `fin_column_width_mm: float
  = 540.0`（仅用于两端外墙位置的柱宽；窗间墙位置柱宽仍取真实窗间墙宽度，
  不受此参数影响）。
- **`core/daylight.py`**：`_fin_slots_full_m()` 两端外墙槽的宽度改为
  `min(fin_column_width_mm, 可用端墙空间)`，贴窗边缘生成，不再铺满整段
  端墙剩余空间。
- **`core/plan_export.py`**：`_fin_slots()`（平面图外凸矩形）、
  `draw_shading_elevation()`（立面柱子）同步改用相同的固定宽度逻辑，确保
  绘图与实际参与计算的柱子形状一致；`draw_dim_chain()` 新增柱宽拆分逻辑
  ——两端"端墙"区段若柱宽小于整段区段长度，自动拆成"墙"+"柱"两段标注
  （如"端墙1310"+"柱540"），与用户CAD图纸的标注粒度一致，便于逐段核对；
  `shading_dimension_lines()` 侧栏文字同步更新为准确描述（此前仍写着
  "仅窗间墙位置，两端外墙不设"，v2.10.0引入端墙翼板后未同步更新，属遗留
  的过时文案，一并修正）。
- **`io_utils/project_io.py`**：`.rlproj` 序列化/反序列化新增
  `fin_column_width_mm` 字段，旧文件无此字段按默认值540mm处理。
- **`ui/sidebar.py`**："遮阳构件（全局默认）"面板新增"端墙柱宽"输入框。
- **验证数据几何核实**：按用户CAD图纸重新核对房间A(411)/房间B(509)的
  房间总宽与窗户位置——两间教室窗户排布完全一致（沿墙西到东：1310mm墙+
  540mm柱+窗1(1250)+540柱+窗2(1250)+540柱+窗3(1250)+540柱+窗4(1250)+
  540柱+窗5(1250)+540mm柱），仅总宽不同：房间A=10800mm（东端柱贴墙角，
  柱外无多余墙体），房间B=11180mm（东端柱外还有380mm墙体到墙角）；此前
  examples里的房间总宽与窗户x坐标存在小误差，一并按CAD图纸修正。

物理校核：柱宽收窄后，`_fin_slots_full_m()` 输出确认全部6处柱子宽度统一
为540mm（此前西端1540mm、东端450/830mm均已修正）；GUI逐窗覆盖面板/
`.rlproj`序列化往返测试通过。

真实教室验证结果（房间A_411/房间B_509，窗1测线）：
- MRE：房间A 128.8%（v2.10.1为130.0%，基本未变）；房间B 292.6%（v2.10.1
  为292.5%，基本未变）。
- **如实报告，未弱化**：柱宽修正本身有明确依据、且是必要的正确性修复
  （现场柱子确实只有540mm宽），但对窗1测线MRE这一具体指标几乎没有影响——
  v2.10.1变更日志中"更宽的端墙槽导致窗1遮挡更强"的归因，经本轮复核**并不
  准确，予以更正**。窗1/窗5比窗2/3/4略暗的现象依然存在但幅度很小，更可能

  无关。窗1测线MRE持续偏高的真正原因仍未查明，不排除是材料反射率/玻璃
  透光率等假设参数与该教室实际情况存在系统性差异（呼应更早版本记录的
  "房间B窗1实测系统性偏暗"未解异常），留作后续独立排查。
- 详见 `examples/教室采光验证_房间411_509/` 与桌面交付文件夹 `说明.txt`。
- **补充修正（测点距离）**：以上MRE用的测线取点是 `--first-offset 0.5
  --spacing 0.5`（5点挤在离窗0.5~2.5m），与8.2m进深不成比例；改为沿进深
  均匀分布 `--first-offset 1.36667 --spacing 1.36667`（六等分进深）后，
  窗1测线MRE骤降至房间A=39.5%、房间B=15.1%（合并测线32.1%/31.6%），说明
  此前的测点距离假设才是长期误差偏高的主因，而非几何/遮阳模型问题。上面
  128.8%/292.6%等数字已过时，见桌面 `说明.txt` 顶部更新与最新
  `验证结果表.csv`。

### v2.10.1
**垂直翼板遮挡几何专项修复（针对v2.10.0已知问题）**

诊断（先于实现）：v2.10.0 交付后发现两处问题，均先与用户讨论确认根因再动手，
未擅自假设：

1. **出挑深度包含墙厚**：与用户核实，标注的850mm出挑深度系从室内参照线
   起算、包含了240mm墙厚，真正伸出外墙皮之外、能挡住天空视线的有效出挑
   只有(标注深度−墙厚)。v2.10.0 直接把标注值当有效出挑代入几何判定，是
   窗户自身沿窗测线被过度压暗的根因之一（并非射线-平面相交算法本身有误，
   该算法经解析法独立核验是精确解）。
2. **窗间墙遮挡在数学上不可能触发**（解析证明，非概率性漏判）：v2.7~
   v2.10.0 把翼板当作贴在"某扇窗户自己边缘"的零宽度虚拟面，只测试该窗
   自身两侧。可证明：只要测点在窗户 w 的横向范围之外（例如窗间墙测点），
   测试 w 自身近侧翼板面时，射线参数恒有 t<1（在到达窗洞面之前就已"穿过"
   翼板所在坐标），使得"遮挡须发生在窗洞面之外(t≥1)"这一条件恒不成立。
   这是 v2.9.1~v2.10.0 一直记录的"窗间墙测点遮挡幅度被系统性低估"的数学
   根源。

修复实现：
- **`core/models.py`**：`ShadingDevice.get_overhang_for()`/`get_fin_depth_for()`
  语义不变；`beam_shade_fraction()` 签名不变。
- **`core/daylight.py`**：
  - 新增 `_fin_slots_full_m(room, wall)`，替代原 `_vertical_fin_positions_mm()`：
    返回该墙全部翼板/装饰柱位置的完整立体槽 `[(u0,u1,D_eff,z0,z1), ...]`（含
    两端外墙+窗间墙），出挑深度已扣墙厚（`max(0, 标注深度−room.thermal.
    wall_thickness_mm)`）。
  - `_ds_point()` 的翼板遮挡判定重写为**射线-立方体(AABB)相交**（标准 slab
    法）：翼板不再是贴在窗户自己边缘的零宽度面，而是按其真实占据的横向
    范围×出挑深度×竖向范围建模为实心长方体；任意窗户的天空面元只要视线
    延伸路径（t≥1）与该长方体有非空交集就算被遮挡，不再限定"只测自身
    两侧"——因为现实中一根柱子会挡住从室内任意角度投过来的、恰好穿过它
    所占体积的视线。
- **`validate_daylight.py`**：新增 `--all-windows`，额外导出该墙全部窗户
  各自沿窗中线的模拟DF到 `全部窗口沿窗中线模拟值.csv`（复用同一次网格
  计算，无额外算力开销），仅命令行指定的基准窗户有实测数据可比对误差，
  其余窗户只有模拟值，用于横向核对是否有异常。

物理校核（受控最小场景，独立于真实教室房间几何，避免多窗户稀释效应干扰）：
- ✅ 深度=0 时与无翼板基线完全一致（回归测试通过）。
- ✅ 深度增大时，窗中心测点与窗间墙测点的DF均单调下降。
- ✅ 窗户自身中心测点的遮挡幅度从 v2.10.0 的约57%（双侧遮挡）软化到约
  33%~53%（视测点距窗距离而定），不再是灾难性放大。
- ❌ **窗间墙测点遮挡幅度大于窗中心测点**——数学上已证明不可能满足：自由
  柱无法遮挡"直接相邻窗边缘"的近距离视线（该视线穿过窗洞面时，恒已偏离
  柱体所在横向坐标）。已与用户讨论并确认**接受当前设计，如实记录该局限**，
  不追加窗洞斜壁(reveal)建模（超出本轮范围，如需彻底解决需引入窗户在墙体
  内的安装位置/洞口斜壁这一新的几何维度，建议作为独立后续任务）。

真实教室验证结果（房间A_411/房间B_509，窗1测线，唯一有实测数据对照的窗户）：
- MRE：房间A 从 v2.10.0 的 98.5% 变为 **130.0%**；房间B 从 237.7% 变为
  **292.5%**——**未改善，反而变差**，如实记录，未弱化。
- 根因（额外发现，超出预期）：窗1恰好是端墙窗，其一侧翼板槽是很宽的
  1540mm端墙槽（窗2/3/4两侧都是较窄的540mm窗间墙槽）。新的"长方体体积
  相交"判定下，更宽的端墙槽给了更多倾斜视线机会落入610mm出挑深度范围内，
  反而让窗1本身的遮挡比窗2/3/4更强（`全部窗口沿窗中线模拟值.csv` 可见
  窗1/窗5模拟DF明显低于窗2/3/4）。即：本轮修复的两个问题本身有依据、
  已独立验证成立，但对"窗1测线与实测数据匹配度"这一具体指标，净效果是

**修正（bug fix）：**
- **外墙 sol-air 太阳附加得热高估约 20×**：旧公式 `α·I·A/R_ext` 把外墙吸热几乎全部计入室内，导致室温虚高（年均42℃/峰值66℃）、遮阳对舒适性失效。改为标准 sol-air 向内传热 `U_wall·A·α·I_vert/h_out`，室温回到合理区间（年均~22℃/峰值~35℃），遮阳得以真正影响热环境。

**已知局限（论文需说明）：**
- 「月中日正午」代表工况下，东/西向窗正午几乎无直射，挑檐对其月度遮阳无效（本项目窗以南向为主）。
- 离散舒适月数在炎热气候下易饱和，主实验帕累托建议用连续量（Σ超温度·月 / 热不舒适度）作热轴。
- 侧窗深房间 U0 本就偏低（<0.70），合规筛选阈值 `--u0-min` 可配置。
- Dext 尚未计挑檐下表面反射补光（代码留 TODO，阶段二实现）；百叶/导光板仍为预留。
